Ping Developer API

A small, predictable HTTP API for building on Ping — send and read messages, open conversations and act on behalf of your own account. JSON in, JSON out, authenticated with a single API key.

Overview

Every endpoint lives under a versioned base URL:

https://example.invalid/api/v1

The API is REST-ish: resources are addressed by path, actions use the obvious HTTP verb, request and response bodies are JSON. Each key acts as a Ping account — your own — so anything the API sends appears to recipients exactly as if you'd sent it from the app, delivered live and via push notification.

Authentication

Send your secret key as a bearer token on every request. A key looks like ping_sk_… and is shown to you only once, when you create it. 

Authorization: Bearer ping_sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

The X-API-Key header is accepted as an alternative.

Treat the key like a password. It grants access to your messages. Never embed it in client-side code or commit it to a repository. Lost or leaked a key? Revoke it (see below) and mint a new one.

Creating a key

Keys are minted from your own signed-in session. Authenticate as you normally would (the same login the app uses) to obtain a session token, then call the key-management endpoints with it.

1 · Log in to get a session token

# returns { "token": "<session-jwt>", "user": {…} }
curl -X POST https://example.invalid/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"login":"+4366012345678","password":"••••••"}'

2 · Mint an API key

curl -X POST https://example.invalid/api/dev/keys \
  -H 'authorization: Bearer <session-jwt>' \
  -H 'content-type: application/json' \
  -d '{"name":"My bot","scopes":["profile","chats:read","messages:write"]}'
// 201 Created — copy "key" now; it is never shown again.
{
  "key": {
    "id": "b2c1…",
    "name": "My bot",
    "prefix": "ping_sk_a1b2…",
    "scopes": ["profile", "chats:read", "messages:write"],
    "key": "ping_sk_a1b2c3d4e5f6…"
  }
}

Managing keys

MethodPathDoes
GET/api/dev/keysList your keys (prefixes only, never secrets).
POST/api/dev/keysCreate a key. Body: name, optional scopes.
DELETE/api/dev/keys/:idRevoke a key immediately.

These three endpoints use your session token, not an API key.

Scopes

A key only grants what you ask for. Request the narrowest set that gets the job done.

profile

Read the key owner's own identity (GET /me).

chats:read

List chats and read message history.

messages:write

Send messages and open direct chats.

Omit scopes at creation to get the default set: profile, chats:read, messages:write.

Conventions

  • Format. Send Content-Type: application/json; all responses are JSON.
  • Timestamps are integer epoch milliseconds (UTC).
  • IDs are opaque strings — don't parse them.
  • Rate limits. Requests are throttled per client. On 429, back off and retry. RateLimit-* headers describe your budget.
  • Errors always look like { "error": "…" } with a meaningful status code.

Identity

GET/api/v1/mescope: profile

Returns the account this key acts as, including its phone number.

curl https://example.invalid/api/v1/me \
  -H 'authorization: Bearer ping_sk_…'
{
  "user": {
    "id": "a1b2…",
    "displayName": "My bot",
    "phone": "+4366012345678",
    "about": "",
    "avatarColor": "#4d9bff"
  }
}

Chats

GET/api/v1/chatsscope: chats:read

List every chat (direct & group) the account is in, most-recent first.

{ "chats": [ /* Chat objects */ ] }
GET/api/v1/chats/:idscope: chats:read

Fetch a single chat you belong to. 404 if it doesn't exist, 403 if you're not a member.

GET/api/v1/chats/:id/messagesscope: chats:read

Message history, newest last. Paginate backwards with query params:

ParamTypeNotes
limitnumber1–100, default 40.
beforenumberReturn messages created before this timestamp (ms). Use the oldest createdAt you have to page back.
curl https://example.invalid/api/v1/chats/CHAT_ID/messages?limit=20 \
  -H 'authorization: Bearer ping_sk_…'
POST/api/v1/chats/directscope: messages:write

Open (or reopen) a one-to-one chat with a user. Idempotent. Address them by any one of:

FieldTypeNotes
tostringUser id, phone (E.164) or email — whichever you have.
userIdstringExplicit user id.
phonestringPhone number, any common format.
emailstringAccount email.
{ "chat": { /* Chat object */ } }

Messages

POST/api/v1/chats/:id/messagesscope: messages:write

Send a message into a chat you belong to.

FieldTypeNotes
bodystringMessage text (≤ 4000 chars). Required for text messages.
replyTostringOptional id of a message in this chat to quote.
curl -X POST https://example.invalid/api/v1/chats/CHAT_ID/messages \
  -H 'authorization: Bearer ping_sk_…' \
  -H 'content-type: application/json' \
  -d '{"body":"Hello from the API 👋"}'
// 201 Created
{ "message": { /* Message object */ } }
POST/api/v1/messagesscope: messages:write

Shortcut: open the direct chat with to and post a message in a single call — the quickest way to DM someone. 

curl -X POST https://example.invalid/api/v1/messages \
  -H 'authorization: Bearer ping_sk_…' \
  -H 'content-type: application/json' \
  -d '{"to":"+4366012345678","body":"Your build is done ✅"}'
{ "message": { /* Message object */ } }
